# Provider word timing implementation plan

**Goal:** Use LRCLIB word timestamps to drive the approved Glow animation, retaining estimated progression for line-only lyrics. The user approved this feature and confirmed rc.3 animation is working; merge and publication of 1.1.0 remain gated on their subsequent phone testing.

**Architecture:** Decode LRCLIB's Lyricsfile 1.0 YAML into optional immutable word segments on each saved line. A pure timeline computes independent segment emphasis from absolute playback time; the existing renderer uses those segments with its unchanged glow, drift and scale. Old stored lines default to no words. No Room schema migration is needed because lyric content is JSON.

**Constraints:** Android min SDK 31; existing JDK/SDK only; existing signing identity; no new services, accounts or permissions. Keep original versions and explicit selections. Never store inferred word times. Do not change the approved animation or overlay gestures. Keep current line-only matching and closest-duration preference; word timing breaks otherwise equivalent matches. New candidate is 1.1.0-rc.4 (13), not a public release.

## 1. Provider parsing and persistence

- [x] Add behavior tests at `lyrics/WordSyncTest.kt` and `lyrics/LyricsfileParserTest.kt`. First demonstrate that the current matcher discards provider word timing.
- [x] Extend `model/Models.kt`: `LyricWord(text, startMs, endMs?)`; append optional `endMs` and default-empty `words` to `LyricLine`. Preserve UTF-16 text ranges by concatenating actual provider segments, including whitespace and non-Latin text.
- [x] Add bounded safe YAML parsing in `lyrics/LyricsfileParser.kt`, using pinned Apache-licensed SnakeYAML. Accept documented version 1.0, integer milliseconds, optional ends, and overlapping words. Reject duplicate keys, unsafe tags, excessive input/nesting/aliases, unknown versions and unresolved nonzero global offsets. Invalid documents fall back to existing LRC/plain parsing; invalid word lists fall back to the unchanged text and line timestamp. No partial word alignment guesses.
- [x] Update `ProviderSong`/`LyricsMatcher` to consume `lyricsfile`, include word/end timing in content identity only when present, and keep old line-only hashes stable. Update `BackupCodec` to validate and round-trip words and ends; old backups remain readable. Preserve word data on unchanged personal-edit lines; clear it when their text or line timing changes.
- [x] Verify parsing, malformed input fallback, matching hashes, editor safety and backup compatibility with JVM tests.

## 2. Playback and Glow

- [x] Add `WordSync` pure functions for segment ranges, validation and emphasis. An explicit end controls its word; missing ends use the next later word start or the line display boundary only for rendering. Gaps hold completed words and do not start future words. Overlaps advance independently. Seek, pause, speed and user delay use the existing playback clock.
- [x] Pass saved segments and playback snapshot to `AnimatedLyricText` from `LyricsReader`. Sample playback on drawing frames for word-synced active lines. Retain existing estimated sweep for lines without valid words. Keep glow styling, layout, shadow correction and drift untouched; do not apply the estimate's 180 ms smoothing delay to supplied word timestamps.
- [x] Label word-, line- and mixed timing in version choices and reader status. Explain fallback in settings. Keep plain editing as default and explicitly explain when editing removes word timing from a changed line.
- [x] Provide a non-destructive way to fetch updated versions for cached songs, preserving existing selections, adjustments and personal edits. Never delete cached lyrics on lookup failure.
- [x] Add regression tests for real unequal word durations, silent gaps, overlaps, missing ends, Unicode segments and pause/seek/speed/delay; compile device rendering coverage.

## 3. Candidate validation

- [x] Run debug/release unit tests, lint, APK assembly and instrumentation assembly using the approved JDK/SDK. Verify the release certificate, matching R8 mapping and ZIP alignment.
- [x] Update notices, changelog, candidate notes and checkpoint; record rc.3 animation as user-confirmed, and word-sync visual verification as pending.
- [x] Review changes, commit/push the feature branch, package the same-key rc.4 APK and remove only the superseded candidate APK. No merge, tag or public release.

Format references: [LRCLIB API](https://lrclib.net/docs.txt) and [Lyricsfile 1.0 draft](https://github.com/tranxuanthang/lyricsfile/blob/main/SPECIFICATION.md). The draft deliberately leaves global offsets and missing end times unspecified; the implementation must not silently fabricate saved timing.
