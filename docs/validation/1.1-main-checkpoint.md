## Translate fix

The previous unit tests verified query encoding but did not cover receiver behavior. A successful `startActivity` cannot confirm that another app used the text; the user reported Translate opening empty. The exact device routing was not captured, so this is not claimed as a reproduced browser/app-specific bug.

The new handoff copies full original lyrics before launching, prefers a browser via an Android selector, and falls back to the ordinary URL handler if the browser cannot open. It preserves Unicode, punctuation and blank lines. Toast and in-app feedback tell the user to paste if needed. A missing handler leaves the clipboard fallback available. If the URL exceeds the transport bound, the English-target page opens without text and the copied original remains available; Google may require sections. Clipboard denial, oversized clipboard input and blocked/missing handlers produce explicit outcomes without partial text or fabricated success.

The Android [Intent selector contract](https://developer.android.com/reference/android/content/Intent#setSelector(android.content.Intent)) allows resolution through the browser category while delivering the outer view intent. The original full-text URL remains unchanged. Google documents a [5,000-character text limit](https://support.google.com/translate/answer/6142478?hl=en). This change adds no permission, account, translation provider or new signing identity.
