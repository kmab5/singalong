Certificate SHA-256: `8B:BE:1D:A9:6D:D0:1E:32:F9:71:D5:16:F1:61:9B:67:C5:A1:5B:52:22:B4:08:64:AD:31:79:F6:2A:EF:6A:04`. Generated 2026-11-01; valid until 2054-03-19. This public fingerprint can be used to verify future release APKs.

Keep a secure backup of **both files** outside this checkout. Future release builds must reuse this key so Android can install updates over the existing release. Do not regenerate it if it is missing. The password was supplied by the user and is deliberately omitted from this document.

GitHub signing now uses encrypted repository secrets containing this same key and credentials. `tools/package_release.py` checks the APK certificate against `release-certificate.sha256` before any artifact upload/publication. The version source is `version.properties`. See [the release guide](../RELEASING.md) for secret names, environment overrides, tag validation and main-branch safeguards. No key is generated by CI.

From PowerShell:

```powershell
$env:JAVA_HOME = 'D:/Code/java/jdk-21.0.12.1'
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug '-Dorg.gradle.java.home=D:/Code/java/jdk-21.0.12.1' --console=plain
.\gradlew.bat :app:assembleRelease '-Dorg.gradle.java.home=D:/Code/java/jdk-21.0.12.1' --console=plain
```

Set `JAVA_HOME` as well as the quoted JVM argument because the wrapper itself otherwise uses the machine's default Java. The release build fails explicitly when signing configuration is missing. Debug builds use the usual Android debug certificate; they cannot update an installation signed with the release certificate. Use release APKs consistently on the test phone to preserve update continuity.

APK paths: `app/build/outputs/apk/debug/app-debug.apk` and `app/build/outputs/apk/release/app-release.apk`. Run `python tools/package_release.py` after the build completes to verify version, certificate, matching R8 symbols and ZIP alignment. See the [current integration checkpoint](1.2-main-checkpoint.md) for build evidence; P6 remains historical.

Release builds enable R8 optimization/obfuscation and resource shrinking. Preserve `app/build/outputs/mapping/release/mapping.txt` alongside each distributed APK's checksum to decode obfuscated crash traces. Packaging writes the current APK, mapping, build information and checksums to `artifacts/release/`. Versioned phone-test copies use `artifacts/singalong-<version>.apk`, `.mapping.txt` and `.build-info.json`. Retain old mappings when removing superseded APKs. These files remain local and ignored by Git.
